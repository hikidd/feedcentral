# FeedCentral Unified Cron Setup

The production deployment uses one Cloudflare Worker schedule. The Worker calls:

    POST https://kidd.one/api/cron/run-all

The unified endpoint:

1. Fetches active global RSS sources.
2. Fetches all enabled user RSS sources.
3. Runs the 7/14-day article cleanup on the first Monday run of each UTC week.

Authentication:

    Authorization: Bearer <CRON_API_KEY>

## Recommended production setup

Configure the Cloudflare Worker in `cloudflare/scheduler/` and do not configure a
second VM crontab or Vercel Cron job. After changing the domain or Worker config,
run:

    cd cloudflare/scheduler
    npm run deploy

## Optional VM fallback

Only use this if the Cloudflare Worker is not enabled. Configure exactly one
hourly entry, with the server cron timezone set to UTC so the weekly cleanup
window is reached reliably:

    0 * * * * /root/scripts/cron-runner.sh >> /var/log/feedcentral-cron.log 2>&1

Set `CRON_API_KEY` in the VM environment before running the script. Do not also
configure the old `fetch-feeds.sh`, `cleanup-articles.sh`, or Vercel Cron jobs.

## Manual verification

    curl -X POST https://kidd.one/api/cron/run-all \
      -H "Authorization: Bearer $CRON_API_KEY" \
      -H "Content-Type: application/json"

To verify cleanup without waiting for Monday:

    curl -X POST 'https://kidd.one/api/cron/run-all?forceCleanup=true' \
      -H "Authorization: Bearer $CRON_API_KEY" \
      -H "Content-Type: application/json"
